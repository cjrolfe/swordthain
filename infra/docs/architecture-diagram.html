System overview

Three clients (the media app, the owner-only playground, and the CLI upload tool) sit in front of two independently-deployed applications, sharing one Cognito user pool for identity. The region split is deliberate — see the note below.

Why two regions: presigned S3 URLs for the media library go straight from a browser to the bucket, bypassing CloudFront entirely — so the media app's data plane (bucket + tables + API) lives in eu-west-1 for UK latency and EU data residency. CloudFront distributions, their ACM certs, and CloudFront-scoped WAFv2 web ACLs can only be managed from us-east-1, which is why the edge layer, Cognito, and the playground stack are pinned there instead.

03

Auth — passwordless sign-in

Every sign-in (browser or CLI) is the same Cognito CUSTOM_AUTH challenge chain — a 6-digit code emailed via SES, hashed and checked server-side. No passwords exist anywhere in this system.

sequenceDiagram
  participant U as Browser / CLI
  participant C as Cognito
  participant Cr as CreateAuthChallengeFn
  participant O as OTP table
  participant S as SES
  participant V as VerifyAuthChallengeResponseFn

  U->>C: InitiateAuth (CUSTOM_AUTH, email)
  C->>Cr: generate challenge
  Cr->>O: store hashed code + expiry
  Cr->>S: SendEmail (6-digit code)
  S-->>U: code delivered
  U->>C: RespondToAuthChallenge (code)
  C->>V: verify answer
  V->>O: check hash + expiry
  alt correct
    V->>C: pass
    C-->>U: access + id + refresh tokens
  else wrong or expired
    V->>C: fail
    C-->>U: new challenge, retry
  end
Token lifetimes: access/ID tokens last 1 hour; the refresh token lasts 365 days and is never rotated — so a signed-in session effectively persists for a year without re-entering a code, refreshing silently in the background.

04

CI/CD — deploy topology

Five independently-scoped GitHub Actions pipelines, each assuming a purpose-built IAM role via OIDC — no long-lived AWS keys stored anywhere. A playground-only change cannot touch infra permissions, and vice versa. Three deploy on a path-filtered push to main; the other two (the regression-test and accessibility-test suites) are triggered by the deploy workflows succeeding, not by a path.
